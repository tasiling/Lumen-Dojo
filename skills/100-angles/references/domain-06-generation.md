# 第六域：生成型运算

## #43 种子句培育

**指令**：从 {book} 中提炼出"种子句"——那些一旦被说出就能生长出整本书的句子。这些句子包含了书的全部DNA。

**Prompt模板**：

对 {book} 执行"种子句培育"：

1. **候选句提取**：从书中找出10个最有"生长潜力"的句子（可以是核心论点句、核心隐喻句、核心问题句）
2. **生长测试**：测试每个候选句——以这个句子为种子，能"生长"出该书的多少内容？
3. **种子句评选**：哪个句子是真正的"种子句"——包含最多生长信息、最能代表全书？
4. **生长机制分析**：这个种子句的生长机制是什么（演绎？归纳？隐喻延展？）？
5. **种子句报告**：输出1-3个核心种子句，并说明每个种子句的生长路径

## #44 逆工程工具箱

**指令**：从 {book} 中提炼可复用的"方法论工具包"。读者在读完这本书后，可以带走哪些可应用于其他情境的具体工具？

**Prompt模板**：

对 {book} 执行"逆工程工具箱"提取：

1. **工具识别**：该书提供了哪些可复用的分析方法/框架/流程？
2. **工具接口定义**：每个工具的输入是什么？输出是什么？适用条件是什么？
3. **工具测试案例**：为每个工具提供1-2个可应用的其他领域案例
4. **工具依赖关系**：工具之间是否有依赖关系？使用顺序是什么？
5. **工具箱清单**：以工具卡片形式输出每个工具的：名称、输入、输出、使用说明、示例

## #45 问题发生器

**指令**：从 {book} 中提炼出该书没有回答、但值得进一步研究的问题。最好的书是能够产生新问题的书。

**Prompt模板**：

对 {book} 执行"问题发生器"：

1. **显性问题提取**：该书明确提出了哪些问题？列出5-8个
2. **隐性问题生成**：基于该书的框架，隐含着哪些没有被明确提出的问题？
3. **元问题发现**：该书的整个论证框架本身提出了什么元层面的问题？
4. **问题价值评估**：每个问题的研究价值有多大？哪些是"大问题"？
5. **问题清单报告**：以研究计划书格式输出，包含问题列表、研究价值评估、可能的研究路径

---

## #46 隐喻引擎

**指令**：从 {book} 中提取核心隐喻，分析其效力与边界。任何隐喻都是"有所见有所不见"的。

**Prompt模板**：

对 {book} 执行"隐喻引擎"分析：

1. **核心隐喻提取**：该书最核心的隐喻是什么？（如"社会是机器"、"历史是战场"）
2. **隐喻效力分析**：这个隐喻让我们"看见"了什么以前看不见的东西？
3. **隐喻盲区识别**：这个隐喻遮蔽了什么？它让我们"看不见"什么？
4. **替代隐喻测试**：如果用另一个隐喻替代核心隐喻，这本书的论证会发生什么变化？
5. **隐喻地图**：以对比表形式展示核心隐喻的所见/所不见，以及替代隐喻

## #47 空白章节

**指令**：识别 {book} 中缺失的视角，为其"补写"一个缺失的章节。如果这本书包含一个被忽视的视角，书的整体叙事会如何改变？

**Prompt模板**：

对 {book} 补写"空白章节"：

1. **空白识别**：这本书最明显的视角空白是什么？（谁没有被听到？）
2. **视角重建**：以被忽视视角的身份，重新"经历"这本书描述的事件
3. **认知冲击分析**：这个新视角会如何改变读者对这本书核心论点的理解？
4. **章节写作**：以300-500字写一个"空白章节"，从被忽视视角描述核心场景
5. **影响评估**：添加这一章后，书的整体叙事和结论会发生哪些变化？

## #48 实验设计

**指令**：设计一个能够验证 {book} 核心假设的实验。从书的核心论点出发，设计可操作的实验来测试它。

**Prompt模板**：

对 {book} 设计验证实验：

1. **核心假设提炼**：该书最核心、可被验证的假设是什么？
2. **实验设计**：设计一个具体可操作的实验，包含对照组、实验组、测量指标
3. **可行性评估**：这个实验在当前技术和资源条件下是否可执行？如不可行，简化版实验是什么？
4. **预期结果分析**：如果实验结果支持假设，说明什么？如果不支持，说明什么？
5. **实验方案报告**：以标准实验报告格式输出，包含假设、实验设计、测量指标、预期结果

## #49 操作系统提取

**指令**：从 {book} 的叙事中提取隐含的"操作系统"——作者默认的底层运行规则是什么？这个世界观建立在哪些不可动摇的公理之上？

**Prompt模板**：

对 {book} 执行"操作系统提取"：

1. **规则提取**：该书的叙事/论证建立在哪些"默认规则"之上？
2. **优先级识别**：这些规则之间是否有优先级？如果规则之间发生冲突，哪个优先？
3. **边界条件发现**：这套"操作系统"的边界条件是什么？在什么情况下会崩溃或报错？
4. **版本检测**：这套"操作系统"是1.0版（尚未成熟）还是已有多个版本迭代？
5. **操作系统报告**：以系统架构文档格式输出，包含核心规则、优先级、边界条件、版本

## #50 悖论收割

**指令**：从 {book} 中识别并放大书中的悖论。悖论不是缺陷——它们是真相浮出水面的地方。

**Prompt模板**：

对 {book} 执行"悖论收割"：

1. **悖论识别**：该书中存在哪些悖论（言行矛盾？价值观冲突？结论与前提矛盾？）？
2. **悖论分类**：这是"真实悖论"（不可化解的结构性矛盾）还是"表面悖论"（可以被消解的）？
3. **悖论价值分析**：这个悖论揭示了什么？它指向什么被回避的真相？
4. **悖论放大实验**：如果把这个悖论推到极致，会产生什么洞察？
5. **悖论报告**：以悖论分析格式输出，包含悖论内容、类型、价值洞察、放大实验结论
