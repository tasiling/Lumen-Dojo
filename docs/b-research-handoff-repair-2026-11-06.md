# B 回覆到研究採用：完整分析與修復

## 問題不是只有介面

實際 B 回覆的文章與研究候選分開是正確的，但網站在跨步驟交接時失去欄位和稿件版本。v10 的「能進討論」不代表能對正確文章完成研究採用。此次沿用原工作台與資料，修復整條交接，不重建獨立工具。

| 環節 | 已重現根因 | 本輪處理 |
|---|---|---|
| 研究回收 | 指令要求英文欄名，純文字辨識卻只認中文；有筆數就不警告 | 中英文欄名皆可，保留人類標題與完整論文題名；逐欄提示缺漏，DOI/完整URL不足另提示 |
| 方向／經驗 | 只接受編號或JSON，漏掉方向表格與experience自然條目 | 支援Tab與Markdown表格、帶來源的經驗條目；候選方向在B可編輯、接入題目；例子仍未採用 |
| 本輪文章 | 無條件選舊正文／原始來源，忽略新候選稿 | 可明確選目前正文、B候選稿、原始草稿；段落列表、討論、整理、整合使用同一選擇 |
| 本人決定 | GPT的框架、收束只在原文，無直接確認交接 | 從討論區列出提及選項及原話；本人按確認才改設定，另記決定輪次，不改本人原回答或正文 |
| 整合採用 | 來源可能不同，候選整合可能蓋掉討論中改過的正文 | 任務固定文章、設定、研究；非正文來源另固定待替換正文摘要。正文變更阻擋舊任務；採用才更新正文並保存舊稿，來源切回目前正文 |

## 作者的實際操作

1. 貼回完整B回覆，辨識並檢查逐筆欄位，再確認分欄；完整回覆仍保存。
2. 如需沿用GPT建議，另外確認框架／收束；也可以保留原設定。
3. 在「本輪討論與整合使用的文章」明確選稿。候選稿不必先採用為正文。
4. 選研究、文章段落，填自己的問題與接續回答，複製指令到GPT；貼回並保存每輪討論。
5. 談清楚後整理重點，逐點核對原文、限制與本文關聯，決定採用／背景／不用。
6. 產生整合指令、貼回變更，預覽每段前後；確認採用才更新正文，保留前正文與原回覆。

## 邊界與回復

- 來源缺漏可以繼續討論與手動補正，不能因此自動視為已查證；沒有引用不等於沒有研究。
- `論文 DOI`引用標籤不是DOI字串。未從其他對話補認書目，未宣稱此次核實兩篇研究的科學內容。
- 框架候選表內的替代方案，不當作討論區主要建議自動設定。確認後只更新設定及決定紀錄，不混入作者回答。
- 舊版備份的文章選擇預設目前正文；既有任務原快照保留，不回填新設定。新任務固定寫作設定，變更後提示過期。
- 重新確認舊的僅標題研究可補空欄，但保留本人已編輯的非空內容；不因重複確認重複加入研究／例子／方向。
- 新版HTML在已交付v10上局部更新。媒體與備份擴充不以repo舊包覆蓋。原生及離線採用轉換皆需測試。

## 對實際回覆的重測

保留原完整文字於暫存，本倉庫不存私人全文。新版識別七段、兩筆研究，四個關鍵欄位皆不空；兩個方向、兩個經驗。兩筆來源均警告缺少可複製DOI／完整URL。候選文章保留，沒有因分欄改正文。

## 驗收方法

先以同結構的虛構資料寫失敗反例，再修純函式／原生服務，最後在兩場域實走HTML與原生。範圍包括候選稿未採用、舊正文不同、設定確認、作者回答、重點判讀、候選段落整合、採用前不改正文、歷史保留、重開、備份還原與媒體保留。

最終結果另見delivery文件。iPhone實機、使用者私人資料及真實GPT回覆內容品質仍須本人驗收；本輪不部署、不合併PR。

## 本輪執行教訓

- 不能用辨識筆數與原文保留宣稱欄位可用；每筆語意欄位與缺漏提示都要核對。
- 不能只測JSON，需覆蓋網站實際指令可能產生的自然表格、英文字段與經驗條目。
- 不能以完整B歷史包含新文章，推導新文章已是正式任務底稿；須核對實際複製的article及採用時驗證基底。
- 測試新增來源模式需同時檢查舊正文改版與舊備份，不能以純函式成功代表離線媒體版也成功。
- 原生測試須以同一隔離server/test行程啟動，等READY再開始；build不得與UI驗收共用正在替換的Next資產。首次廣泛回歸遇到Internal Server Error，須從穩定最終build重跑，不能忽略。
