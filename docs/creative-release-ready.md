這份文件是部署前的可操作交接，不代表已部署。審閱入口：[PR101](https://github.com/tasiling/Lumen-Dojo/pull/101)。精確 Native／GitHub head、相同 tree、最新 master 衝突檢查見同一份 `creative-build-progress.md` 最後 checkpoint；本文件隨該 commit 保存。

## 目前可用的開發成果

來源與公開設定、閱讀筆記／洞察／知識主張、允許來源的主動提案、文字五步與三平台稿、圖文、短影音、Podcast、短漫、長影片、固定成品交接，以及依版本／平台保存的私人發布紀錄與回看。每種媒體的實際試製與尚未驗證的上限見各 `creative-*-delivery.md`；腳本、來源包與最終檔分開保存。

發布紀錄由本人填寫外站結果，不能自動發文。排程日期只供安排；不會自動轉製或排所有平台。保留原發布欄位，沒有批次搬動正式資料。

## 部署環境必須具備

- Node >=20.9、專案鎖定套件，`npm ci`、`npm run build`。Next 16.2.10 的 Node runtime；不能部署為純靜態站。
- 可執行且版本相容的 `ffmpeg`／`ffprobe`，含 H264/AAC 解碼。上傳會完整檢查，不只看副檔名；圖片使用 Sharp。
- 既有 `ACCESS_KEY`、`NOTION_TOKEN` 與原本正式 Notion 資料庫設定，沿用現有機密管理；不要將密鑰寫進 repo、截圖或日誌。
- `LEARNING_WRITE_LOCK_DIR` 為可寫的絕對持久磁碟路徑，重啟／換版後仍保留，僅授權服務帳號存取。它同時保存 global writer lock、weaving-operations 收據、來源／提案操作，以及 `illustrated-assets`、`short-video-media`、`podcast-media`、`long-video-media`。不是可以隨容器重建清空的 cache。
- 單一寫入主體，或所有實例確實共用同一個具正確鎖語意的檔案系統。現有本機檔案鎖不保證不同 host 各用獨立磁碟時仍能防重；未驗證多 host，不能用擴容代替共享鎖確認。
- 代理／平台上傳限制與請求時限須容納媒體及完整檢查。產品上限短片64MiB、Podcast128MiB、長片256MiB，不能因此推論正式代理一定接受；先在隔離環境驗證實際目標。

## 備份與回復

1. 部署前暫停寫入，保存當前正式 commit、環境設定版本及資料庫備份；確認備份不包含意外公開的私人原文。
2. 將 Notion 資料與整個持久目錄作一致時間點的備份；媒體採 SHA 定址，資料與檔案必須一起還原。收據與未知操作鎖也須保留，不能只備份影片。
3. 先在隔離還原環境確認資料庫引用、圖片／音訊／影片 SHA 與 Range 讀取，重新啟動後仍能讀到檔案及操作收據。
4. 新版出現問題時先停止寫入並保存現場，再回復部署前版本與對應一致備份；不要在舊版仍持續寫入時任意回灌舊資料庫。
5. 結果不明的寫入保持鎖，先以 operation receipt／marker 唯讀核對；不得為恢復服務直接刪鎖或盲目重送。依確認的遠端結果處理，避免新增副本。

新增發布紀錄有獨立 prefix，沒有不可逆批次遷移。回復舊版時新紀錄可能暫不顯示，應保留資料，不能刪除以配合舊介面。

## 正式發布時的驗收順序

1. 取得當前整合版 merge／deploy 授權，核對 PR 精確 head、最新 master 與其他工作區變更。不要重試此前已取消的 Railway 操作。
2. 在隔離的持久環境建置相同 tree，用專用測試資料庫與虛構題材先跑來源、提案、文字、六形式交接與發布紀錄；重啟再讀固定媒體／收據。不能用正式私人日記驗試。
3. 手機實際測試：375／390／430px，320px可用性與1024px擴充；本人常用瀏覽器檢查字型、H264／音訊播放、下載及重新開啟來源包。自動瀏覽器截圖不代表真機驗收。
4. 以一件本人選定的低敏感素材測語氣、版面與提案品質；公開權限逐份確認。本人聲音另以本人選定錄音測試，不把非語音提示音當錄製完成。
5. 確認後再合併／部署，查看登入、讀取、保存、失敗復原與媒體 Range；再決定是否開始本人實際內容製作。沒有社群自動公開動作。
