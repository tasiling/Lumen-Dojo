# 晨間啟動與日復盤 v2

## 資料策略

- 創現角色仍使用 DB-14 的單一 JSON 紀錄 `行光創現角色`，沒有新增平行角色庫。
- 創現角色由 v1 正規化為 v2，新增穩定 `id` 與 `messages[]`。角色稱號、特質或方向更新時，API 會保留留言。
- 每日紀錄仍使用 `行光今日-YYYYMMDD`，一天一筆並以 upsert 更新。每日 schema 由 v1 升為 v2；舊紀錄只在讀取時正規化，不做批次覆寫。
- 道場日期以 `NEXT_PUBLIC_DOJO_TIME_ZONE` 決定，未設定時使用 `Asia/Taipei`。舊函式名稱保留作相容層。

## DailyRecord v2 新欄位

### morning

- `capacity`: `low | medium | high | null`
- `selfNote`: 此刻的我
- `roleSnapshot`: 當日創現角色的 id、稱號、特質與方向快照
- `roleMessageId`: 已保存角色留言的 id；一次性留言可為 null
- `roleMessage`: 當日實際使用的角色留言快照
- `roleReply`: 使用者對角色的選填回覆

既有 `state`、`creativeState`、`intention`、`gratitude`、`affirmation`、`futureJournal` 均保留。`intention` 在新版 UI 顯示為「今天的選擇」；舊 `state` 讀取時會映射到新的行動餘裕，但不刪除原值。

### evening

- `practiceReflection`: 今天的實踐回望

既有 `highlight`、`block`、`insight`、`nextAction` 只更換 UI 名稱，不移除資料。

## 深度顯示

- 晨間輕量：此刻的我、創現角色、角色留言與回覆、今天的選擇。
- 晨間適中：加上感謝與晨間正向肯定句。
- 晨間深入：再加上未來日記。
- 晚間輕量：一束光、實踐回望。
- 晚間適中：再加卡點與消耗、今天的發現。
- 晚間深入：再加下一次的小調整。

深度只控制欄位顯示；切換時不清空其他深度已輸入的內容。

## 相容與遷移

- 無破壞性或批次資料遷移。
- v1 每日紀錄缺少新欄位時以空值補齊；舊欄位原樣保留於正規化結果及回看／完整匯出。
- 舊角色紀錄缺少 `id` 時使用 `primary`，缺少留言時使用空陣列。
- 晨間首次保存時建立角色快照；後續修改角色不會回寫舊日記。
- 晨間與晚間仍更新同一日的同一筆每日紀錄，避免重複資料。
