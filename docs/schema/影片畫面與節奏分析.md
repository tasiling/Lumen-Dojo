# 行光道場｜影片畫面與節奏分析

2026-11-26。用於抖音小動畫這類「想學它怎麼做」的影片：拆出分鏡、鏡頭運動、轉場與剪接節奏，再把值得學的手法存成手法觀察卡。

## 流程

1. 影片要先由 Mac 轉錄過（抖音連結，或放進 iCloud「行光轉錄」資料夾的檔案）。
2. 在採集詳情的「畫面與節奏」區塊按「分析畫面與節奏」。不會自動分析。
3. Mac 接手後：
   - 抖音影片從官方播放器重新取得；檔案從收件資料夾或 `~/Movies/行光轉錄封存` 依雜湊值找回。
   - 用 FFmpeg 量出鏡頭切點（場景變化門檻 0.3），每秒取 4 張候選畫面，縮成寬 480 的 JPEG。
   - 每個鏡頭依序取開頭、中段、結尾畫面，總數最多 48 張。切點常晚報一到兩格，所以開頭取切點後的第一張、結尾留 0.1 秒餘裕，確保畫面屬於自己的鏡頭。
   - 只傳送縮圖、時間與切點；影片本身不離開 Mac。
4. 行光道場收到畫面後，交給 AI 描述每個鏡頭（畫面、鏡頭運動、元素動作、轉場、字幕）、說明節奏、列出三到八個手法，以及看不清楚的地方。完成後用 LINE 通知。
5. 在網頁核對分鏡，按「確認分鏡，帶進淬鍊」。
6. 每個手法可以寫下自己的話，按「存成手法觀察卡」。

## 不失真的界線

- 切點、鏡頭時間、最短最長鏡頭、最快的三秒，都是 Mac 量出來的確定值；AI 不能改鏡頭的時間，少了任何一個鏡頭就整份不收。
- 畫面之間的動作是從前後畫面推測的，手法會標「畫面可見」或「依前後畫面推測」。
- 沒有分析聲音，節奏只看剪接，不推測音樂拍點。
- 手法觀察卡一定要有擁有者自己的話（「我的原話」）；AI 的分析與鏡頭時間放在引用欄。標題沿用手法名稱時標為「整理版」，改過就標為「改寫」。

## 與淬鍊的關係

- 只有確認過的分鏡會進入淬鍊原文，以「〔畫面與節奏〕」分段，每個鏡頭一行，最後一行是節奏。原文種類加上「畫面與節奏，已核對」。
- 重新分析會取代舊分析並取消確認；已存的手法觀察卡會保留在洞察卡庫。

## 資料

- 採集紀錄的 `clip.videoAnalysis`：狀態（queued／working／reading／ready／failed）、影片長度、切點、逐鏡頭描述、節奏、手法（含已存卡片編號）、待核對處、是否確認、讀取時間、模型與估計費用。
- 手法觀察卡存在洞察卡庫，出自討論為「影片分析 <採集編號> #<手法序號>」，同一個手法重存不會重複建卡。
- Mac 佇列的 `analysis` 表記錄排隊、租約與進度（取得影片、切畫面、傳送）。轉錄工作優先，沒有轉錄時才接分析。
- 費用與英文影像、圖片文字共用 `OPENAI_ENGLISH_IMAGE_MONTHLY_BUDGET_USD` 的每月預算。

## 更新 Mac

Mac 的連線程式要更新才會接分析工作：在「Mac 轉錄設定」重新下載配對檔並執行一次。舊版程式會讓網頁顯示更新提示。

## 檔案

- `lib/dojo/videoAnalysis.ts`：資料格式、分析指令、節奏計算、併入原文與手法觀察卡的規則（純規則）。
- `lib/dojo/videoAnalysisReader.ts`、`app/api/dojo/captures/[id]/video-analysis/route.ts`：排入、讀畫面、確認、存卡。
- `app/api/integrations/douyin/worker/[action]/route.ts`（`analysis` 動作）、`lib/dojo/douyin/queue.mjs`：Mac 取件與回傳。
- `lib/dojo/douyinMac/media.py`、`lib/dojo/douyinMac/worker.py`：切點量測、選畫面、上傳。
- `app/components/CaptureVideoAnalysisPanel.tsx`：採集頁的「畫面與節奏」區塊。
- 測試：`npm run test:video-analysis`。
