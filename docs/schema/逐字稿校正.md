# 逐字稿校正（簡轉繁與辨識修正）

版本 v0.1｜2026-11-24｜擁有者指示：「影片逐字稿類型的，都還是要加上 AI 整理，不是那種
AI 的摘要式整理，而是把逐字稿的辨識修到順暢的程度，而且要把簡體轉為繁體也是必須的。」

【已裁決】是擁有者說過的要求；【待裁決】是尚未決定、暫以所列預設進行的部分。

## 原則

- 【已裁決】校正不是摘要。不刪句、不增句、不換說法、不調整順序。
- 【已裁決】簡體一律轉為繁體。
- 沿用野採「不失真」的規則：原始辨識結果永遠保留，校正版另外存放，兩者都能查看。

## 資料

`clip.transcript` 現有 `text`、`finishedAt`、`truncated`，不改動、不覆寫。新增：

| 欄位 | 內容 |
| --- | --- |
| `transcript.tidy.text` | 校正後的全文，保留分段 |
| `transcript.tidy.at` | 完成時間 |
| `transcript.tidy.model` | 使用的模型 |
| `transcript.tidy.changes` | 改動筆數；逐筆內容不存，需要時由兩版比對產生 |
| `transcript.tidy.state` | `done`、`failed`、`skipped`（超出預算或太短） |

## 處理順序

1. 簡轉繁：用字形對照表轉換，只換字、不換詞（例如「视频」轉成「視頻」，不改成
   「影片」）。【待裁決】是否連詞彙一起換成台灣用語；預設不換，因為那已經是改寫。
2. 辨識修正：交給模型，只允許四種改動——同音或近音的錯字、標點、斷句、分段。
   聽不出來的地方保留原樣並標上〔？〕，不得猜測補字。口語的贅詞與重複照留。
3. 長稿依段落分批處理，每批帶前一批的最後兩句當上下文，避免斷在句子中間。

## 機器檢查（校正版要通過才會被採用）

- 去掉標點與空白後，校正版與繁體原稿的字數相差不得超過 3%。
- 逐段比對，任何一段的改動比例超過 15% 就視為改寫，該段退回繁體原稿。
- 校正版不得出現原稿沒有的整句。
- 沒通過的部分使用繁體原稿，並在素材頁標示「這幾段沒有校正」。

## 介面

- 素材頁的逐字稿預設顯示校正版，可切換「原始辨識」，並可開啟「改了哪裡」的對照。
- 淬鍊的討論包以校正版為原文，標頭註明「逐字稿，經校正」；段落編號以校正版為準。
- 既有的逐字稿提供「補做校正」按鈕；之後轉錄完成時自動執行。
- LINE 的完成通知在校正結束後才送出，失敗時仍通知，並說明目前顯示的是原始辨識。

## 費用

沿用英文影像分析的做法：使用既有的 OpenAI 金鑰，另設每月上限。【待裁決】上限金額；
預設每月 2 美元，超過時只做簡轉繁，不做辨識修正。

## 本輪不做

- 依影片畫面校正專有名詞。
- 說話者分離。
- Threads 貼文的簡轉繁（貼文是作者原文，維持原樣）。【待裁決】擁有者是否也要轉。

## 變更後三問

- 動到哪些既有資料：只在 `clip.transcript` 底下新增 `tidy`，原始逐字稿不變。
- 失敗時會怎樣：保留並顯示原始辨識，素材仍可使用。
- 怎麼復原：刪除 `tidy` 即回到現況。
