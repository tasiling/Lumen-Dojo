# 逐字稿校正（簡轉繁與辨識修正）

版本 v0.1｜2026-11-24｜擁有者指示：「影片逐字稿類型的，都還是要加上 AI 整理，不是那種
AI 的摘要式整理，而是把逐字稿的辨識修到順暢的程度，而且要把簡體轉為繁體也是必須的。」

【已裁決】是擁有者說過的要求；【待裁決】是尚未決定、暫以所列預設進行的部分。

## 原則

- 【已裁決】校正不是摘要。不刪句、不增句、不換說法、不調整順序。
- 【已裁決】簡體一律轉為繁體。
- 沿用野採「不失真」的規則：原始辨識結果永遠保留，校正版另外存放，兩者都能查看。

## 資料

`clip.transcript` 現有 `text`、`finishedAt`、`truncated`，不改動、不覆寫。新增：

| 欄位 | 內容 |
| --- | --- |
| `transcript.tidy.text` | 校正後的全文，保留分段 |
| `transcript.tidy.at` | 完成時間 |
| `transcript.tidy.model` | 使用的模型 |
| `transcript.tidy.changes` | 改動筆數；逐筆內容不存，需要時由兩版比對產生 |
| `transcript.tidy.state` | `done`、`failed`、`skipped`（超出預算或太短） |

## 處理順序

1. 簡轉繁：用字形對照表轉換，只換字、不換詞（例如「视频」轉成「視頻」，不改成
   「影片」）。【待裁決】是否連詞彙一起換成台灣用語；預設不換，因為那已經是改寫。
2. 辨識修正：交給模型，只允許四種改動——同音或近音的錯字、標點、斷句、分段。
   聽不出來的地方保留原樣並標上〔？〕，不得猜測補字。口語的贅詞與重複照留。
3. 長稿依段落分批處理，每批帶前一批的最後兩句當上下文，避免斷在句子中間。

## 機器檢查（校正版要通過才會被採用）

- 去掉標點與空白後，校正版與繁體原稿的字數相差不得超過 3%。
- 逐段比對，任何一段的改動比例超過 15% 就視為改寫，該段退回繁體原稿。
- 校正版不得出現原稿沒有的整句。
- 沒通過的部分使用繁體原稿，並在素材頁標示「這幾段沒有校正」。

## 介面

- 素材頁的逐字稿預設顯示校正版，可切換「原始辨識」，並可開啟「改了哪裡」的對照。
- 淬鍊的討論包以校正版為原文，標頭註明「逐字稿，經校正」；段落編號以校正版為準。
- 既有的逐字稿提供「補做校正」按鈕；之後轉錄完成時自動執行。
- LINE 的完成通知在校正結束後才送出，失敗時仍通知，並說明目前顯示的是原始辨識。

## 費用

沿用英文影像分析的做法：使用既有的 OpenAI 金鑰，另設每月上限。【待裁決】上限金額；
預設每月 2 美元，超過時只做簡轉繁，不做辨識修正。

## 本輪不做

- 依影片畫面校正專有名詞。
- 說話者分離。
- Threads 貼文的簡轉繁（貼文是作者原文，維持原樣）。【待裁決】擁有者是否也要轉。

## 變更後三問

- 動到哪些既有資料：只在 `clip.transcript` 底下新增 `tidy`，原始逐字稿不變。
- 失敗時會怎樣：保留並顯示原始辨識，素材仍可使用。
- 怎麼復原：刪除 `tidy` 即回到現況。

## 實作說明（v0.1 實作，2026-11-24）

三個【待裁決】事項依預設實作：只換字不換詞、每月上限 2 美元、Threads 貼文不轉。

- **簡轉繁**：`opencc-js` 的 `cn → tw`。它只換字；遇到一對多的字（头发→頭髮、后来→後來、
  干净→乾淨）依詞組挑對的字，並套用台灣字形。不使用會換詞的 `twp`（視頻→影片）。轉換前後字
  數不變。程式在 `lib/dojo/douyin/tidy.ts`。
- **辨識修正**：OpenAI Responses API，模型預設與英文影像分析相同（`OPENAI_TRANSCRIPT_TIDY_MODEL`，
  未設定時用 `OPENAI_ENGLISH_IMAGE_MODEL`，再沒有則 `gpt-5.6-luna`）。每月上限為
  `OPENAI_TRANSCRIPT_TIDY_MONTHLY_BUDGET_USD`（預設 2），與英文影像的上限分開計算；開始前以字數
  估算費用，估算會超過上限時只做簡轉繁。少於 30 字的逐字稿不呼叫模型。
- **段落**：沿用素材頁依時間戳的分段。模型逐段回傳同編號的段落，不能合併或拆編號；要分段時
  在段內加換行。校正版的第 n 段與繁體原稿的第 n 段一一對應，段與段之間以空行分隔。
- **機器檢查**（`lib/dojo/douyin/tidyText.ts`）：比較時不計標點、空白、換行與〔？〕。
  - 逐段：改動比例以編輯距離除以原段字數計算，超過 15% 退回繁體原稿。
  - 整句檢查：校正段裡任一句（五組以上相鄰字）有一半以上的相鄰字組不在原段中，視為原稿沒有
    的整句，退回。
  - 全文：逐段檢查後，字數與繁體原稿相差超過 3% 時，全部退回。
  - 全部段落都退回時，狀態記為 `failed`。
- **新增欄位**：`transcript.tidy.reverted`，退回繁體原稿的段落編號，素材頁據此標示「這幾段沒
  有校正」。
- **`failed` 與 `skipped` 的 `text`**：存繁體原稿（只轉繁體的原始辨識），素材頁仍可切換到原始
  辨識。
- **`changes`**：校正版與繁體原稿逐段比對後的改動處數，簡轉繁不計入。「改了哪裡」由轉錄佇
  列重建繁體原稿後比對，不另存。
- **既有的逐字稿**不會自動校正，由素材頁的「補做校正」觸發，且不發 LINE 通知；新的轉錄完成時
  自動校正。
- **Notion 長度**：原始辨識與校正版放在同一筆紀錄，有校正版時各佔一半空間；放不下時兩者都截
  短，並把 `transcript.truncated` 設為 true，完整內容仍在轉錄佇列。

## 本人貼回的校正版

在別處（例如和 GPT 討論時）完整校正過的逐字稿，可以在素材的「逐字稿」區塊用「貼回校正版」放回來。

- 存放位置與自動校正相同：`clip.transcript.tidy`，`model` 為「本人貼回」，`state` 為 `done`。原始辨識（`clip.transcript.text`）不會被取代。
- 貼回的版本可以自由重新分段，所以不做逐段比對，而是整份和繁體原稿比較：字數差、原稿裡找不到的句子（開場白、小結、改寫）、貼回版本裡找不到的段落（被刪或被改寫）。
- 三項都沒有問題時直接採用；有出入時先列出來，由本人決定修改後再核對，或仍要採用。系統不會自行改動貼回的文字。
- 之後可以用「改用自動校正」換回系統的校正。
