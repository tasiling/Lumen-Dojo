# 行光道場｜LINE 剪藏入口第一階段

## 定位

LINE 只作為「擷取」的外部入口。網址進入既有野採採集匣；單獨圖片進入野採場域中的
英文影像匣，只有使用者主動選擇「一般剪藏」才轉成一般採集紀錄。不會自動建立織光案、今日三件事或週盤格。

## 支援範圍

- 純網址：保存網址，嘗試擷取標題、描述、預覽圖與平台。
- 純圖片：原圖上傳到獨立英文影像紀錄，不保存於 Railway 暫存磁碟；可分為遊戲英文、英文日常或一般剪藏。
- 補截圖：網址剪藏回覆中的「補截圖」按鈕會開啟十分鐘附加窗口。
- 用途：內容觀點、視覺參考、學習資料、待研究、先收著。
- 去重：LINE message ID 與正規化網址重複時不建立第二筆。
- 安全：驗證 `X-Line-Signature`，並只接受 `LINE_ALLOWED_USER_ID`。

英文類型圖片會由 GPT-5.6 Luna 做 OCR、圖像理解與英文整理；一般剪藏不分析。
原圖與原始網址永遠保留，後續摘要不會覆蓋它們。

## Railway 環境變數

```text
LINE_CHANNEL_SECRET=
LINE_CHANNEL_ACCESS_TOKEN=
LINE_ALLOWED_USER_ID=
OPENAI_API_KEY=
OPENAI_ENGLISH_IMAGE_MODEL=gpt-5.6-luna
OPENAI_ENGLISH_IMAGE_MONTHLY_BUDGET_USD=2
```

第一次設定時可先留空 `LINE_ALLOWED_USER_ID`。完成 LINE webhook 驗證並傳一則訊息給
機器人後，它會回覆該帳號的 user ID；把它填回 Railway 後重新部署即可。未設定擁有者
期間不會寫入任何擷取資料。

## LINE Developers 設定

Webhook URL：

```text
https://lumen-dojo.up.railway.app/api/integrations/line/webhook
```

啟用 webhook，並關閉 Official Account Manager 內與剪藏入口衝突的自動回覆。

## 固定選單與文字指令

正式服務啟動時會以 `LINE_CHANNEL_ACCESS_TOKEN` 檢查並安裝預設 Rich Menu。安裝程序可重複執行；同名選單存在時會沿用並重新設為預設，不會持續建立副本。若 LINE 暫時無法連線，選單設定會記錄警告但不阻止網站啟動。需要手動重設時執行：

```bash
npm run line:rich-menu
```

Rich Menu 提供野採圖片、剪藏網址、最近一筆、待整理、豆倉與使用說明六個入口。對應文字指令為：`野採圖片`、`剪藏網址`（亦接受 `貼網址`）、`最近一筆`、`待整理`、`豆倉`、`幫助`／`選單`。

「野採圖片」以 Quick Reply 提供 LINE 原生相機、相簿與「分次收一組」；「最近一筆」會跨一般剪藏與英文影像比較擷取時間，叫回正確的整理按鈕；「待整理」會計算兩區待處理數量並提供野採連結。

使用 LINE 相簿一次選取多張圖片時，系統依 webhook 的 `imageSet.id`、`index` 與 `total` 自動建立同一組素材，不以傳送時間猜測關聯。若圖片需要分次傳送，先按「分次收一組」，傳完後再按「完成這組」；未開啟收圖模式的單張圖片一律建立獨立紀錄。AI 只在圖片組完成並選擇英文類型後執行，一組最多分析十張。

## 英文影像匣延伸

單獨傳入 LINE 的圖片預設寫入 `行光英文影像-` 紀錄，並顯示於野採的英文影像匣。使用者可在 LINE 選擇「遊戲英文」、「英文日常」或「一般剪藏」；前兩者保留獨立英文影像資料，後者才把同一個 Notion 頁面轉為 `行光捕捉-`，因此原圖不會遺失或重複保存。

完成英文影像分析後，LINE 會成為野採的快速整理台，提供：

AI 回覆會直接呈現「英文事件紀錄」、「中文理解」、「可學詞句」與獨立的「單字候選」，不需要先開啟網站才能判斷學習價值。可學詞句保存可跨情境使用的片語、搭配與完整句型；單字候選供 VocabForge 選擇，兩者不混在一起。

- `補充情境`：下一則文字追加到母紀錄。
- `修正原文`：下一則文字取代 OCR 英文，不自動消耗 API 重新分析。
- `繼續補這組`：明確指定最近一筆為目前收圖目標，之後傳入的圖片才會附加到該筆素材。
- `完成這組`：關閉目前圖片組，再進行英文分類與 AI 分析。
- `撤銷誤合併`：拆回舊版「合併上一張」造成的最近一次合併，還原為兩筆獨立素材。
- `送語境修習室`：保留野採母紀錄並產生語境修習入口；目前先使用資料連結，待語境修習室接收 API 完成後再改為直接同步。
- `送 VocabForge`：從 AI 建議中選擇單字逐一匯入，每筆最多三個；片語與句型不進單字庫。
- `兩邊都送`：先備妥語境素材，再讓使用者選擇 VocabForge 單字。
- `先留野採`：不派送、不刪除，之後再整理。

派送只建立衍生資料或連結，不會搬走或刪除野採的圖片、OCR、情境與 AI 結果。野採仍是母紀錄與唯一整理場域。

選擇英文類型後，系統以 OpenAI Responses API 的圖片輸入與嚴格 JSON Schema 一次完成英文 OCR、B1–B2 事件紀錄、中文解釋與可學詞句。原圖永遠保留；辨識信心低或 API 失敗時只改變分析狀態，不覆蓋或移除圖片。

Railway 需設定：

- `OPENAI_API_KEY`：OpenAI Project API key。
- `OPENAI_ENGLISH_IMAGE_MODEL`：預設 `gpt-5.6-luna`。
- `OPENAI_ENGLISH_IMAGE_MONTHLY_BUDGET_USD`：預設 `2`，依已完成紀錄的 token 用量估算本功能當月支出並停止新分析。這是應用端防護，不等同 OpenAI 帳戶的硬性消費上限。

每張圖自動分析一次；重新分析只能由英文影像匣手動觸發，且介面會先提示再次使用 API 額度。`store: false` 固定關閉 Responses 儲存。
