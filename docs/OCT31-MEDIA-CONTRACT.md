# 媒體成品底座｜2026-10-19

本包接續既有織光杼與成品版本，不另建作品系統。先提供漫畫／影片、文字工作流程的圖卡／限動共用資產清單；各工作臺與 Podcast 仍按主排程後續實作，本包不宣稱完成。

- 草稿可有空清單。確認媒體成品必須有明確資產：穩定 ID、版本、HTTP(S) 外部檔案連結、相符 MIME 與實際尺寸／時長。清單是使用者提供的檔案描述，不能當成伺服器已下載驗證檔案或已發布。
- 圖卡固定 4:5、限動固定 9:16；漫畫為逐格順序的圖片；短／長影片成品需影片資產。文字稿、畫面備註、只有外站首頁連結皆不能代替這份資產清單。
- 媒體清單沿既有 revision、operation ID、持久鎖與未知結果恢復機制保存；不新增上傳服務／付費 API。規模上限 100 個資產，拒絕重複 ID、非正整數尺寸及無效時長。
- 成品版本固定清單與來源選摘；預覽摘要包含媒體清單，換檔後必須重新預覽。交接指向固定成品並保留該份清單，日後改草稿不能改舊成品或舊交接。
- 新確認漫畫／影片不再以 article 類型保存；已有舊版本保持原狀。來源 ID、來源版本與擷取日期沿用既有伺服器核對來源，不接受清單另行偽造。

實作順序：隔離真實 store 回歸先見證失敗 → 資產規格與格式核對 → 既有保存／確認／交接接合 → 文字與媒體回歸、build、審查。下一包以此契約接實際輸出與工作臺，另加音訊作品形式與音訊流程。

保存邊界：派送前檢查完整 JSON（含操作標記），限制180,000字元及實際 rich_text 外包裝450,000 UTF-8 bytes，為 Notion 100元素／500KB上限保留餘裕。確認成品先預檢完成後作品快照，避免先建成品才發現回寫過大。超限回413，零派送、不截斷。[Notion request limits](https://developers.notion.com/reference/request-limits)（2026-10-19核對）。
