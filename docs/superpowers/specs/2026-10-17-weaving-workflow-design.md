日期：2026-10-17（Australia/Melbourne）

## 1. 目的與已確認方向

Crystal 已同意沿用「共用創作骨架＋各形式專屬流程」，開始整理建置範圍。目標是在手機上把一份成熟素材製作成文字作品，能中途保存、稍後繼續，再手動交給聊解室整理成可發布版本。

維持三個責任層：織光杼保存來源與核心觀點；作品保存這次的形式、過程與成品；聊解企劃保存平台版本、發布安排與回看。作品與修習成果、知識採用、週盤完成各自保留原語意。

本文件把上一輪對話的流程落成資料與行為規格。建議的首批範圍是五種文字工作流程；漫畫與影片另行分階段製作。未把上述後續功能當作已完成。

| 項目 | 已核對存在的實作 | 本輪需要補齊 |

| 閱讀 | `/reading`、書籍內的讀前／讀中／讀後、洞察卡 | 精確選摘與來源定位；沿用原資料 |

現有 `chooseWork` 會直接替換本機 draftText；`patchWork` 在回應後也直接以伺服器內容設定 draftText。因此第一批必須覆蓋切換作品、保存等待期間繼續輸入等情境。這是程式閱讀發現的缺口，尚未執行行為重現或宣稱已修正。

現有作品 PATCH 未提供 expectedRevision，建立母卡／作品為多次 Notion 寫入。並發、回應遺失與部分完成需納入首批行為設計；不能把前端 disabled 視為完整保護。

## 3. 範圍與跨視窗邊界

### 本階段交付

- 精確選取來源片段、確認本件作品核心觀點。
- 素材、構思、製作、確認、交接五個可返回的操作步驟。
- 長文、短貼文／噗浪、IG 輪播文案、IG 限動文字、口播稿五種模板。
- 已有草稿直接續作；保存狀態、未保存離開防護與版本衝突呈現。
- 逐頁／逐段內容排序與編輯；合成可貼回、可複製的完整文字。
- 完成版本與聊解室手動交接；保留創作後回杼。
- 隔離 API／儲存與手機尺寸行為驗收，交付獨立 PR。

### 本階段排除

- 完整漫畫生成器、影片剪輯器、IG 圖卡排版器、錄音系統。
- 自動發布、社群帳戶連接、新付費 AI API、媒體大量複製。
- 書籍整本匯入、全文自動改寫、知識自動採用、素材自動升成熟度。
- 修習所、野採、週盤及語境修習室的整體 UI 重製。
- 閱讀分類與可管理學科的全面合併；這是獨立銜接包，並非文字作品的前置阻擋。
- 舊織光案批次遷移、正式資料 backfill、正式發布。

其他視窗持續負責共用設計規範與各自頁面。此分支僅修改織光堂／聊解室專屬元件與必要 API；共用 CSS、底部導覽、圖示與 tokens 的改動另列提案。實作 UI 前取得現行設計交接規範，不自行發明另一套品牌配色。

## 4. 使用者操作

### 4.1 建立或繼續

首頁先顯示近期未完成作品與其具體下一步，再提供建立入口。建立時先完成三個決定：素材、最想說的一句話、作品形式。受眾與發布安排可後補。

既有作品直接打開原作品；「另做一件」是獨立操作。多次返回、刷新或查看來源不建立新作品。核心觀點改版不悄悄改動既有作品採用的 coreVersionId。

### 4.2 五個步驟

| 步驟 | 畫面與操作 | 保存結果 |
| --- | --- | --- |
| 素材 | 選擇來源、勾選片段、確認帶入內容 | 本作品的來源選摘與時間快照 |
| 構思 | 本件核心重點、受眾、結構／大綱 | 明確的作品方向與結構草稿 |
| 製作 | 本形式的分段編輯、協作指令、外部工具、貼回候選 | 各段內容與工作草稿 |
| 確認 | 完整文字預覽、引用檢查、返回修改、確認完成 | 不可被一般編輯覆寫的成品版本 |
| 交接 | 收藏／暫放／手動送往聊解室 | 已交接版本與原作品的穩定關聯 |

步驟可返回，不以完成百分比或連續天數呈現。畫面顯示「現在狀態」與一個具體下一步，例如「補上第 3 頁的例子」。編輯草稿可以留白；確認完成時才驗證成品的必要條件。

## 5. 來源選取與知識閱讀後台

### 5.1 資料落點

| 資料 | 繼續保存的位置 | 織光堂引用方式 |
| --- | --- | --- |
| 書籍／閱讀輪次 | DB21 書籍庫 | 書籍 ID、閱讀問題及定位 |
| 閱讀筆記 | 原書籍頁面區塊 | note ID、kind、章節／位置及選中片段 |
| 洞察卡 | DB22 洞察卡片庫 | insight ID、狀態、自己的理解與選中內容 |
| 野採 | 原 Capture 記錄 | capture ID、可定位來源及所選片段 |
| Knowledge Claim | DB14 原 Claim JSON | claim ID、採用的 version ID、允許用途與選中片段 |
| 織光杼／作品／聊解企劃 | DB14 各自既有前綴的 JSON | 原實體 ID 不變；增加可選欄位 |
| Learning Record | DB14 原學習正文 JSON | 原引用保持；首批不自動生成正文或完成事件 |

### 5.2 選摘規則

- 第一版提供既有已驗證／不成立洞察、符合現有 C2/C3 與 adopted 門檻的野採、手動成熟題材。
- 閱讀想法可增加明確的「整理為創作題材」動作：使用者選片段並補自己的觀點後，才可建立作品；純原文收藏維持在閱讀區。
- 候選選擇器可顯示來源摘要；送往外部 AI 的協作指令只包含明確選中的內容及必要來源資訊，不偷偷附帶全文。
- 頁碼、章節、來源網址、來源 ID 與擷取時間一起保存。原文摘錄、個人理解與經驗分別標示。
- Claim 以採用版本與 allowedUses 檢查用途；未採用候選不冒充已採用知識，AI 候選身分保留。創作靈感不被表述為已驗證事實。
- 伺服器重讀來源並驗證類型、可存取性及成熟度；不信任前端傳回的 ownership、來源全文或成熟狀態。
- 缺失／封存來源保留歷史引用與當時快照，顯示目前不可用；新採用須重新核對。
- 來源更新後提示可查看新版本，由使用者選擇更新作品素材；不自動覆蓋已完成作品。

### 5.3 回寫界線

作品完成不修改原閱讀格式、不自動建立 Claim、不提升 Claim 成熟度、不自動計入學成或週盤。回杼產生新理解時，使用者可另行保存知識候選，仍走原人工審閱流程。

## 6. 五種文字模板與完成條件

| 模板 | 製作結構 | 本階段可交付成品 |
| --- | --- | --- |
| 長文 | 讀者問題、開頭、主段落、例子／引用、收尾 | 有內容的完整文章；各部分可自訂或省略 |
| 短貼文／噗浪 | 唯一重點、開頭、例子／感受、收尾；可拆樓 | 有順序的單篇或串文 |
| IG 輪播文案 | 封面、逐頁重點／文案、結尾；可調頁序 | 完整逐頁文案；明示圖卡製作尚未完成 |
| IG 限動文字 | 分享目的、各張短句、配圖備註、可選互動 | 有順序的限動文字與畫面備註 |
| 口播稿 | 約略時長、開場、各段講述、例子、收尾 | 可試讀的完整腳本；明示音訊／影片另行製作 |

模板只作為可編輯起點，不要求每欄必填。使用者可增加、刪除、排序段落；已輸入內容不可因切換模板被清空。更換模板先預覽轉換，保留原工作版本。

每一步可手動寫作，也可複製包含「本步目標＋已選素材＋既有草稿」的協作指令。長文／輪播／限動／口播繼續採複製指令與貼回；噗浪沿用 `/plurk` 工具入口。不存在的外部工具不呈現可用假按鈕。

完成條件是確認文字成品與其交付類型；外部成品連結可補充。沒有稿件或成品內容時不能標記完成。輪播文案、口播稿不被標示成完整圖卡或影片。

## 7. 模型與相容設計

WeavingShuttle 保留 v3，WeavingWork 保留原 v1 recordType 與既有欄位。以可選 `textWorkflow` 增補工作資料，內含 schemaVersion=1、templateKey、currentStep、blocks、sourceSelections、outputKind。每個 block 使用穩定 ID、用途標籤、文字及必要媒體備註；順序由陣列維持，名稱不作身分。

`draftText` 維持完整文字相容投影；有結構化 blocks 時由同一 serializer 合成，明確整篇貼回則建立候選版本，確認後才替換。不得同時把兩份互相矛盾的文字當權威。自由文字舊稿讀為一個自由段落，不假拆大綱。

新增 `revision`（舊資料讀取時為 0）、`completionVersionRefs` 與 `currentCompletionVersionId`。每個成品版本在 DB14 以獨立前綴 `行光作品成品-v1-` 逐筆保存，作品只保留引用，避免多份長文堆在同一 JSON。單次完成快照包含文字、outputKind、來源選摘、coreVersionId 與完成時間；建立後僅可撤回或標示被新版本取代，原快照不得覆寫。後續修訂保留前一成品，既有 finalSnapshot 維持目前成品的相容投影。新增前綴需排除於一般知識內容掃描之外。

來源選摘至少保存 sourceType、sourceId、來源版本資訊（確實存在才填）、定位、內容種類、selectedText、capturedAt。來源沒有原生版本時保存擷取時間與內容摘要雜湊，不捏造權威版本號。

每件作品的合成文字上限沿用 80,000 字元，選摘快照合計上限 30,000 字元、最多 30 個來源／選摘項目。伺服器在 normalize 前拒絕超限並保留本機輸入，不默默截斷成品或來源。outputKind 固定為 article、post、thread、carousel_copy、story_copy、spoken_script；未設定的舊稿以目前 formatSubtype 顯示推定交付種類，需使用者確認後才建立新成品版本。

LiaojieProject 增加可選 sourceCompletionVersionId 與交接操作身分；保留原 weavingShuttleId／weavingWorkId、文字快照及核心版本。既有已送出作品不自動重建。

沒有這些新欄位的舊資料照常讀取；只在明確保存時寫入新增欄位。所有舊記錄類型與前綴沿用，不新增平行資料庫。舊版 API 不得在新增欄位後以整筆舊 payload 清掉新資料。

## 8. 保存、衝突與交接恢復

- 本機編輯緩衝與伺服器已確認版本分開。每次保存綁定當時的編輯序號；回應到達時只更新該版本的保存基準，不覆蓋其後輸入。
- 表單顯示未保存／保存中／已保存／保存失敗。主動保存是主要方式；本階段不依賴背景計時自動寫入。
- 切換作品、返回與站內跳頁提供保存後離開、放棄、繼續編輯。刷新／關閉使用可支援的原生離開提示；不承諾手機強制終止程式時可保存尚未送出的輸入。
- PATCH 使用 expectedRevision 與欄位白名單；在共用持久寫入鎖中讀取、驗證、保存。版本不符回 409 並保留本機輸入，提供並列查看與重新套用，不靜默覆蓋。
- 多筆建立與交接使用持久 operationId／收據。重送同一操作核對相同輸入並回傳同一實體；同 ID 不同輸入回衝突。
- 對已送出但結果不明的建立，保留意圖與鎖並提供唯讀查詢；不以新的隨機 ID 重建。先核對是否已存在，再恢復缺少的後續步驟。
- 沿用 learningFoundation 已有的持久鎖與結果分類原則，為創作操作增加獨立命名空間的控制收據；不刪除或重用其他工作包的 lock／intent。
- 交接以作品 ID＋成品版本作唯一對應。同一版本重送回原企劃；新成品版本到達時提示另建發布版本，由使用者明確選擇。來源作品與已交接快照保持可回查。
- 「安排發布」只是保存日期；外部發布與平台授權不在本包。標記已發布仍要求發布連結。

## 10. 交付分批與每批終點

| 批次 | 可檢查的交付結果 |
| --- | --- |
| W1 | 既有稿件安全保存／續作、版本衝突與建立／交接恢復；相關隔離行為測試 |
| W2 | 選來源片段、五個步驟與五種文字模板；可完成一件文字成品 |
| W3 | 完成版本、聊解室手動接收與回杼；完整手機尺寸流程驗收 |

本表是範圍與交付順序，不是已批准的逐檔執行計畫或時間承諾。每批完成即保存 checkpoint，避免等全部功能齊備才保存成果。具體實作計畫在本文審閱後依最新程式制定。

## 11. 驗收案例

1. 從既有作品續寫，保存後刷新，仍回到原作品與步驟，ID 不變。
2. 保存送出後再輸入新文字；舊保存回應不吃掉新輸入，仍顯示尚未保存。
3. 切換作品時取消離開，原輸入保留；確認保存後離開再返回可恢復。
4. 兩個頁籤編輯同作品，舊 revision 保存回衝突，兩邊資料可查看。
5. 選兩段閱讀內容，只把這兩段與必要來源帶入協作指令；未選全文不流出。
6. 原文摘錄與自己的理解分開；不合成熟門檻的野採或失效知識不得偽裝可用來源。
7. 五種模板各可保存結構、排序、預覽、完成與重新開啟。更換模板前可檢查原內容。
8. 完成稿 A 後修訂為 B，已交接 A 保留原快照，作品能回看 A／B。
9. 建立／交接回應遺失及重啟後，沿用同 operationId 讀回同作品／企劃；不重複建立。
10. 母卡建立成功、子作品尚未確認時，可辨認部分結果並恢復，不隨意封存不明結果。
11. 聊解室預覽後保存、安排日期或補發布連結；保存作品不觸發對外發布。
12. 舊織光案、舊文字稿、既有閱讀筆記、Claim 與學習正文照常可讀；GET 不做遷移或建資料。
13. 375／390／430px 與桌面測試長中文、逐頁內容、鍵盤、安全區、返回／刷新及可操作按鈕。

隔離測試使用測試 adapter／資料，不使用正式筆記作失敗注入。真實 Notion 與 iPhone Safari 驗收分別標記，不能以 Chromium 或服務 SUCCESS 代替。實作時先讀 AGENTS.md 與本版 Next.js 文件，再執行相關行為測試、型別、lint、build 與 diff check；不以字串檢查代替保存／重試行為測試。
