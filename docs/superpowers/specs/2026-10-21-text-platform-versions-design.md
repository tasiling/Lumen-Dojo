# 第四包：純文字與三平台版本設計

日期：2026-10-21（Australia/Melbourne）

## 目標與完成定義

把織光堂已固定的文字成品，在全零聊解室內製成一個使用者明確選定的平台版本。第一版支援噗浪樓層、Threads 一般貼文串、Instagram 貼文配文；不得因選定一個題材便自動產生全部平台版本。

完成不是只有提示詞，而是一份能在產品內編輯、預覽、保存、回復舊版、固定為可發布狀態並完成平台交接的實際稿件。以隔離素材完成「文章固定成品 → 聊解室 → 選一平台 → 修改語氣 → 保存版本 → 預覽 → 可發布 → 交接」作為本包驗收。

## 已確認的產品裁定

- 核心成果優先順序維持：同頻交流、觀看分享、個人特色、服務轉換。
- 原稿是固定來源，不因平台改寫而變動；平台稿件可持續演化。
- 平台由本人逐一建立。已建立的版本可切換，但系統不自動全平台轉製。
- 受眾、CTA、排程可以留白；不推測尚未決定的偏好。
- AI／外部工具提示詞只是協作入口；產品內仍需保存真正可交付的稿件。
- 噗浪使用既有蓋樓工具；Threads、Instagram 先採人工複製與發布連結回收，不做帳號登入或自動公開。
- 本輪沿用已授權的持續建置與例行取捨。未合併 PR 可修訂，故不再停下等待重複核准；代價是正式資料與真機仍需後續驗收。

## 資料模型

### 平台版本索引

每個 `LiaojieTextVariant` 只屬於一個聊解企劃及一個平台：

- `publicationId`、固定來源 `sourceCompletionVersionId` 與 `sourceDigest`
- `platform`: `plurk | threads | instagram_post`
- `revision`：索引的樂觀鎖版本
- `currentVersionId`、`versionRefs[]`
- `status`: `draft | ready | scheduled | published`
- `scheduledOn`、`publishedUrl`
- 噗浪交接後的 `plurkDraftId` 與 `plurkSourceVersionId`

同一聊解企劃與同一平台只允許一個索引；操作重送不得建立副本。

### 不可覆寫稿件版本

每次保存建立一個新的 `LiaojieTextVersion`：

- `variantId`、遞增 `number`
- `title`
- `voiceNote`：這版想保留的語氣／節奏
- `changeNote`：本次修改意圖
- `blocks[]`: 穩定 ID、角色與文字
- `createdAt`

回復舊版不是改寫歷史，而是以舊版內容建立一個新版本。平台索引只移動目前版本指標。

### 平台稿件結構

- 噗浪：主噗與樓層；每段依既有產品規則顯示 360 字檢查。
- Threads：一般貼文串；每段顯示 500 字檢查。
- Instagram：一段配文，可分段但作為單一 caption 交接；本包不把非官方或未驗證的長度當伺服器硬限制。

初稿由固定原稿做可逆的段落整理，不新增觀點、不偽造 Crystal 語氣。介面明示「來源整理草稿，仍需本人改語氣」。

## 伺服器操作與失敗恢復

所有建立、保存、改狀態及噗浪交接都使用既有 durable operation receipt：

1. 建立平台稿：先建立不可變稿件版本，再建立平台索引。
2. 保存修改：先建立新版本，再以 `expectedRevision` 更新索引。
3. 標記 ready／scheduled／published：重新讀目前版本並驗證區塊；發布前重新核對固定來源的公開許可。`published` 必須有 http(s) 連結。
4. 未知回應保留相同 operation ID；重新整理後唯讀核對，不重建副本。
5. 衝突回 409，瀏覽器保留輸入並提供目前伺服器版本比較／重套。

噗浪交接以平台 variant ID 與 version ID 寫入 draft metadata。相同版本重送回傳同一 draft；新版明確交接時更新工作草稿，不另建副本。此動作只建立／更新蓋樓草稿，不公開發文。

## 介面

聊解室工作台仍以固定來源卡開始，其下改成四步：

1. 選平台：只建立本人按下的平台版本。
2. 改語氣：編輯標題、語氣註記、修改註記與有序文字區塊；提供外部 AI 改寫指令複製入口。
3. 預覽定稿：產品與預覽共用同一稿件預覽元件；修改後須重新預覽。
4. 準備發布：保存 ready、安排日期、標記發布；噗浪另有「送到噗浪蓋樓」。

歷史版本在稿件下方列出，可檢視並以舊版建立新版本。通用舊發布欄位保留為相容資料，但不再作為新文字流程的主要入口。

## 視覺與響應式

沿用聊解室藍色系、織光堂粉藍漸層與既有字體；不新增平行設計系統。

- 主色：`#253c5c`；互動藍：`#45638f`；淡藍底：`#eaf1fc`；邊線：`#d6e3f2`。
- 標題沿用現有宋體語彙，正文沿用現有無襯線字體。
- 手機單欄；平台卡、區塊編輯器與底部動作在 320px 不橫溢。
- 1024px 擴充為來源／稿件兩段清楚的閱讀寬度，不把整個編輯器攤成難讀的超寬行。
- 辨識特徵是「固定來源紙張＋可抽換的平台稿件頁籤＋版本年輪」，而非一般社群排程表。

自我檢查：介面若只剩平台 logo、文字框與排程日期，會退化成通用 CMS。因此固定來源、單平台選擇、稿件區塊、語氣註記、版本年輪與噗浪蓋樓交接都是不可刪的產品語意。

## 驗收矩陣

- 尺寸：375／390／430／320／1024px 真實渲染；320 無橫向溢出。
- 狀態：無平台稿、有平台稿、未保存、保存失敗、修訂衝突、未知回應恢復、版本回復、ready、scheduled、published、噗浪交接。
- 資料：原稿不變；一平台不建立其他平台；保存產生歷史；重送無副本；公開許可撤回時阻止新的 ready／交接。
- 品質：相關 domain/API/UI 測試、build、typecheck、lint；完整分支唯讀審查後一次修正並重跑。

## 明確不做

- 不登入或自動發到社群。
- 不購買外部服務。
- 不替本人決定受眾、CTA、發布頻率。
- 不把 IG 圖卡、短影片、Podcast 等後續包偷算為本包完成。
- 不改寫固定原稿或正式 Notion 來源資料。
