## 1. 目的與已確認方向

讓 Crystal 能清楚找到閱讀筆記、閱讀洞察與知識主張，理解內容的來源、後續用途，並按書籍、主題與關聯學科查找。保留各自用途與原位置，新增整合總覽；不搬移原始資料、不把閱讀變成必須完成的知識或創作流水線。手機優先，保留完整原功能。

使用者已確認對話中的安排並要求建置。本次規格涵蓋入口、關聯、搜尋與學科篩選；不包含漫畫、影片、錄音、週盤或其他工作區的視覺重設。

## 2. 現況與設計依據

- `/reading`：書架；`/reading/books/[id]`：讀前、閱讀中、讀後。書籍每輪讀次有各自 ID（DB21），筆記為書籍頁面內原有區塊。
- `/reading/cards`：洞察卡片庫（DB22）；來源書籍為關聯，部分卡片的頁面區塊保存來源筆記 ID 與文字快照。舊卡可能只有來源書籍。
- `/dao/knowledge`：知識主張管理（DB14 JSON）。既有 `sources`、主張版本、採用者與允許用途必須保留。
- 知識主張目前分為待理解、評估中、目前採用與演化紀錄；新候選不能自動升格。
- 織光堂作品與成品版本已保存來源類型、來源 ID、版本與選摘快照。閱讀選摘 ID 帶書籍前綴，知識主張的閱讀來源可能只有筆記區塊 ID，需在查找層統一辨識。
- 學科沿用修習底座 `kind=item` 的 LearningEntity，避免再建立一份固定學科清單。

## 4. 使用流程

1. 記下一則筆記，可以單純保存，也可明確選擇提煉洞察、建立知識候選或選摘到織光堂。
2. 洞察保留來源與個人發現；行動、驗證結果不是保留洞察的前置條件。本包不取消目前創作素材的成熟門檻。
3. 建立知識候選仍由使用者操作；採用、升級成熟度與允許用途沿用既有規則。
4. 開啟「來源與後續」可回看直接來源，以及哪些洞察、知識或作品實際引用這筆內容。
5. 在總覽搜尋「按摩」時，可以找到不同種類資料；點結果回原管理頁。看到資料不代表取得創作使用資格。

## 5. 資料邊界與關聯讀取

使用統一的內容識別：`kind + recordId + parentBookId?`。書籍為一個讀次，不能因同名合併不同讀次；筆記必須核對其所屬書籍。

關聯由現存直接引用推導：筆記→洞察、筆記／洞察→知識版本、來源選摘→作品／成品。方向以實際來源為準，不能只靠同名、同主題或同學科推測。列表去重以內容 ID；同一作品的多次選摘合併顯示，版本仍可分辨。間接關聯必須標示經由哪筆內容，不冒充直接引用；第一版僅展示直接關聯。

舊洞察沒有筆記 ID 時，只顯示可確認的來源書籍與歷史快照，不猜筆記。以筆記 ID 回溯舊 Claim 時，必須先從可存取書籍確認唯一歸屬；歧義則顯示無法確定。織光堂的 `bookId:noteId:reflection` 需區分原筆記與理解片段，保留來源版本。舊知識來源無版本時明示「建立時快照，未記錄來源版本」。

採用讀取整合層，重用現有查詢及業務規則；不將一般搜尋接在只列成熟素材的 weaving-sources 上。搜尋與關聯不能新增、改寫原內容或成品快照，不建立第二份主內容。

## 6. 分類與學科

原書籍分類、洞察主題標籤完整保留，不強制轉成學科。總覽分開提供「原有分類／主題」及「關聯學科」，不把兩者混為同一欄位。

新增可選的內容分類註記，保存自訂主題與多個關聯學科 ID。筆記、洞察與知識可個別標記。原書籍註記可作為筆記與洞察的「來自書籍」學科；明確區分直接標記與繼承，允許關閉繼承。新註記不修改原來源內容，也不改知識版本或成熟度。

註記用 DB14 獨立前綴 `行光閱讀知識分類-v1-` 儲存，schema 包含 owner、內容識別、topics、learningItemIds、inheritBookSubjects、revision、時間。缺少註記時視為未分類且允許繼承書籍註記；新增不寫空白記錄。每筆內容只有一筆有效註記，寫入沿用共享持久鎖、操作收據與修訂衝突檢查，不能靠先查再建避免重複。

學科選項取自既有 LearningEntity items，能標示已暫停／封存項目。不能在此自動初始化學科。已存在的失效學科 ID 顯示「學科已不可用」並保留，使用者可移除。原有資料尚未分類仍可搜尋。新增前綴須排除於一般知識正文與 AI 資料包掃描，避免把管理資料當知識。

## 7. 搜尋、篩選與載入

搜尋範圍為閱讀筆記正文及理解欄位、洞察及行動結果、知識標題與目前主張；版本歷史由原管理頁查看，不混入預設結果。可篩選書籍讀次、資料種類、既有主題、自訂主題、關聯學科；不同篩選條件取交集。結果卡顯示類型、摘要、出處、狀態及開啟原紀錄按鈕；搜尋不自動採用內容。

後端按來源分批列舉，提供游標及各來源完成／失敗狀態。第一批先回可用資料，20 筆一頁；未完成時明示「已搜尋部分資料，可繼續載入」，不能宣稱全庫無結果或完整總筆數。載入下一批時延續相同查詢與篩選，改條件作廢舊請求；單一來源失敗可重試，其餘結果保留。游標僅由伺服器簽發，綁定 owner、查詢與篩選，不接受任意 Notion 頁面 ID。

第一版不建立外部搜尋服務或向量庫。可用短期伺服器記憶快取減少重複讀取，但回應需標示讀取時間、提供重新整理，分類寫入後失效相關快取；不得把快取當主資料或跨擁有者共用結果。

## 8. API 與安全邊界

新增 authenticated read API：`GET /api/dojo/reading-knowledge`（總覽）、`GET /api/dojo/reading-knowledge/relations`（直接關聯）；分類用獨立讀寫 API。沿用原有 access-key session，owner 與資料庫由伺服器決定。

所有單筆讀寫先核對來源資料庫／頁面歸屬、有效內容類型與學科 ID，禁止客戶端指定資料庫。分類輸入限制：最多 20 個主題、每項 40 字；最多 20 個學科；拒絕重複、未知欄位及過期 revision。未知寫入結果依原持久收據查核，不能盲重送。來源刪除後仍保留已建立的作品與歷史引用，不顯示可以開啟不存在的筆記。

## 9. 手機介面與驗收

- 沿用現有共用版型、字級、間距與圖示；頁面樣式限本包範圍，避免覆寫其他工作區。
- 搜尋框與選單尺寸一致；篩選可收合，已選條件以可取消標籤顯示，提供全部清除。

- 驗證同名不同讀次、反思片段、舊卡缺來源、來源被刪、空資料、單來源失敗、大量分頁、學科封存、未分類、重複點擊與修訂衝突。

- 跑相關閱讀、知識、織光堂與學習底座既有測試，加本包業務測試；TypeScript、lint、build 及實際手機尺寸互動檢查。
- 正式 Notion 寫入與 iPhone Safari 實際驗收分開回報，不能以 fixture 或 Chromium 測試宣稱正式驗收通過。
