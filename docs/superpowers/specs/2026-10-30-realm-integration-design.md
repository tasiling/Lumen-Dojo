# 作品怎麼在兩邊流動

## 個人創作交給聊解室運用

來源選摘、A 探索與方向理解先留在織光堂，B／C 或其他製作工具完成作品。本人確認定稿後，選「交給聊解室」及要使用的版本。聊解室接收固定版本，修改品牌標題、配文、封面文案及行動邀請，不回寫原正文。

修改原作時保存新版本，聊解室顯示「來源有新版」，由本人決定是否更新該次運用；舊版平台稿與已發表內容保留。純文字可以直接交接；圖文、音訊與影片按真正輸出類型標示，腳本、提示詞、匯入預覽與實際成品分別呈現。

## 聊解室從活動需求開始製作

在活動或服務中按「製作本次內容」，帶入已填好的活動主題、需要的成品、對象與期限，開啟共用製作工作台。保存活動需求與作品的關聯；返回活動時找得到同一份稿件與成品。原則上採連結與明選版本，不能因每次返回入口都另建副本。

服務的集體訊息與每人各自的解讀分開保存。小儀式由 Crystal 非同步進行，不把參與者排成同步線上課。沒有填問題的參加者仍有個別訊息；後續提問的次數與期限維持可設定，不代定承諾。

## 發布回應再回到創作

聊解室的實際文章與交流紀錄，可明確送回原作品或方向，接 A 討論或 D 延伸。保留來源文章及版本。語氣庫取樣以實際發表文本為準；未採用候選、預排稿與模擬發布均不算樣本。

# 資料與權限先接好

入口分開不代表建立兩套作品。正式資料至少要能連起來源、探索、織光杼、方向及理解版本、作品、定稿／成品版本、平台稿與實際發布、活動／預約／私人交付。

- 作品可暫未歸杼。每個方向各有理解版本；作品採用來源和理解的快照，之後修改方向不回寫舊成品。
- 文字定稿與各媒體既有固定輸出，以統一的版本參照供選取與交接；參照保留原本種類、作品、版本與來源，不把影片、漫畫都硬塞成文字成品。
- 同一建立請求重試只產生一筆；同來源與理解接續既有草稿。本人明確另做一件時仍可另建，不能把防重變成每方向只能一件作品。
- 不按標題刪稿。相同舊副本保留原 ID 對照；來源、理解、母稿版本、正文、模組或歷史不同的作品分別保留。
- 保存、跨頁切換、重新開啟使用正式保存契約；未知寫入結果以原操作查收據，保存失敗保留輸入，衝突提供比較與重套。
- 讀取、對外 AI／Canva 使用及公開使用分開決定。私人服務交付和社群公開使用是兩種用途，前者不能被迫公開，後者仍需明確核對權利與私人細節。
- 客戶問題與個別解讀預設只在服務範圍處理，不自動送進公開作品、主動提案或語氣樣本。

舊資料先備份再試遷移，保留原 ID、原稿、歷次校訂、未歸屬探索、A／B／C／D、研究、例子、定稿、平台稿與資產。正式舊「核心經線版本」依每件作品實際採用關聯映射到方向與理解；不確定相同時保留分列與待核對狀態。HTML JSON、五項原工具的 IndexedDB／專案備份及正式資料是三類來源，需分別提供對照與匯入預覽；同一檔案再匯入不新增副本，失敗可還原。
